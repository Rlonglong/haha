# 03 · 新增一張資料表

**做完這篇,一張新的來源表就會自動從 FTP(或落地目錄)進到 SQL Server。**
從頭到尾照做即可,不需要跳到其他文件。

以下用 `T_NEW_TABLE` 當範例,請自行替換成你的表名。

---

## 開始前:先決定這張表長什麼樣

| 問題 | 影響哪個設定 |
|---|---|
| 檔案是我們去 FTP 抓,還是對方推到我們目錄? | `use_ftp_fetch` |
| 檔案是 zip 還是 csv? | `use_ftp_zip` |
| 檔案有沒有表頭?需不需要套檔規補欄位名? | `use_data_rule` |
| 有沒有敏感欄位要加密?(帳號、身分證) | `encrypt_fields` |
| 需不需要客製化清洗? | `has_clean_func` |
| 每天一個檔還是每月一個檔? | `freq` |
| 資料量大嗎?需要索引/分區嗎? | `use_index` / `use_partition` |

---

## Step 1 · 在 SQL Server 建好資料表

**Dagster 不會幫你建表**,以下都要先在資料庫做好:

- [ ] 目標表 `dbo.T_NEW_TABLE`(欄位、型別、以及一個日期欄位如 `TABLE_DATE`)
- [ ] **如果要用 `bcp_target`**:建對應的 View(例如 `v_BCP_T_NEW_TABLE`)
      通常用來對齊 BCP 的欄位順序,或排除自動編號欄位 (BCP 要求若是搬進 Table，所有欄位需要完全一致，由於設計上我們會多一個 Seq_ID，改用 View 就可以傳入)
- [ ] **如果要用索引**:建好索引,記下名稱
- [ ] **如果要用分區**:建好 partition function / scheme / filegroup,
      以及封存表 `T_NEW_TABLE_Archive`(**結構必須跟本表完全一致**,否則無法 SWITCH)

---

檔案位置:`dagster_workspace/dagster_code/table_mapping.py`

### 最簡版(對方推檔到我們目錄、不加密、不清洗)

```python
"T_NEW_TABLE": {
    "input_folder": "/run/media/root/D/data/fromFPP/T_NEW_TABLE",
    "output_folder": "/run/media/root/D/data/T_NEW_TABLE/T_NEW_TABLE_CLEANED",
    "template": "T_NEW_TABLE_{date}.csv",
    "freq": "daily",
    "delimiter": "|",
    "retries": 3,
    "retry_delay_sec": 60,
},
```

### 完整版(FTP + zip + 檔規 + 加密 + 清洗 + 索引 + 分區)

```python
"T_NEW_TABLE": {
    # ---------- 0. FTP 下載 ----------
    "use_ftp_fetch": True,
    "ftp_remote_dir": "/data/fromFPP/T_NEW_TABLE/",
    "ftp_remote_filename_prefix": "T_NEW_TABLE_{date}",
    "use_ftp_zip": True,
    "zip_inner_filename": "EXNP_XXXX",       # zip 內檔名跟外層不同時才要給
    "staging_subfolder": "T_NEW_TABLE",
    "archive_dir": "/run/media/root/D/data/archive/T_NEW_TABLE",

    # ---------- 1. 路徑與基礎 ----------
    "input_folder": "/run/media/root/D/data/fromFPP/T_NEW_TABLE",
    "output_folder": "/run/media/root/D/data/T_NEW_TABLE/T_NEW_TABLE_CLEANED",
    "template": "T_NEW_TABLE_{date}.csv",
    "freq": "daily",
    "delimiter": "|",
    "use_data_rule": True,

    # ---------- 2. 處理邏輯 ----------
    "has_clean_func": True,

    # ---------- 3. 容錯 ----------
    "retries": 3,
    "retry_delay_sec": 60,

    # ---------- 4. BCP ----------
    "bcp_target": "v_BCP_T_NEW_TABLE",

    # ---------- 5. 索引 ----------
    "use_index": True,
    "index_name": "IX_T_NEW_TABLE",

    # ---------- 6. 分區 ----------
    "use_partition": True,
    "partition_function": "pf_NEW_Monthly",
    "retention_years": 2,
    "archive_table": "T_NEW_TABLE_Archive",

    # ---------- 7. 加密 ----------
    "encrypt_fields": ["ACT_NO", "ID"],
},
```

### 分隔符號請不要用逗號或 `|`

兩者都**實際被使用者輸入打敗過**——備註欄位裡有逗號、email 欄位裡有 `|`。
目前改用罕見符號(例如 `〨`)。理由與換符號時要一起確認的事項,
見 [附錄 A · delimiter](../附錄/A_table_mapping設定詳解.md#delimiter)。

### 只想手動跑、不要自動觸發

加一行 `"manual_only": True`。**`freq` 還是要照實填**(它決定日期格式,不填會讓檔名變成 `YYYYMM` 對不上)。

### 幾條會讓 Reload 直接失敗的規則

> 完整的錯誤訊息對照表在 [附錄 A · 載入時就會失敗的錯誤一覽](../附錄/A_table_mapping設定詳解.md#載入時就會失敗的錯誤一覽)。

| 規則 | 說明 |
|---|---|
| 開了 `use_ftp_fetch` 就**必須**給 `archive_dir` | 否則報「必須提供 archive_dir」 |
| `ftp_remote_template` 與 `ftp_remote_dir`+`prefix` **二擇一** | 不能同時給 |
| `ftp_remote_dir` 與 `ftp_remote_filename_prefix` **必須成對** | 只給一個會報錯 |
| 沒開 FTP 就**必須**給 `input_folder` | 否則報錯 |
| 表名、`bcp_target`、`index_name`、`partition_function`、`archive_table` | 只能英數字與底線,不可數字開頭 |
| `staging_subfolder` | 只能英數字、底線、連字號,不可含 `/` 或 `..` |

## Step 3 · VM1 上要配合的事

### 3-1 清洗函式(只有設了 `has_clean_func: True` 才需要)

> **為什麼要在 VM1 做?**
> 如果在 VM4 定義函式再序列化(pickle)透過 SSH 傳過去執行,等同於遠端執行任意程式碼,
> 是明確的注入風險。所以清洗邏輯**一律直接寫在 VM1 上**,Dagster 只傳「表名」這個字串過去。

**① 建立清洗函式檔**

路徑:`/home/bcp_runner/scripts/clean_functions/T_NEW_TABLE_CLEAN.py`

```python
import pandas as pd


def clean_t_new_table(input_path: str, output_path: str, partition_date: str):
    """T_NEW_TABLE 的清洗邏輯。

    參數固定是這三個，由 clean_remote.py 傳入：
      input_path     來源 CSV（前一階段的產物）
      output_path    清洗後要寫出的 CSV
      partition_date 分區日期，格式 YYYY-MM-DD
    """
    df = pd.read_csv(input_path, sep="|", dtype=str, keep_default_na=False)

    # ── 在這裡寫你的清洗邏輯 ──
    # 例：去掉前後空白
    df = df.apply(lambda col: col.str.strip() if col.dtype == "object" else col)
    # 例：補上分區日期欄位
    df["TABLE_DATE"] = partition_date
    # 例：丟掉關鍵欄位為空的列
    df = df[df["ACT_NO"].str.strip() != ""]

    df.to_csv(output_path, sep="|", index=False, encoding="utf-8")
```

> `clean_functions/` 已經設定成會自動 import 底下所有 def,所以**不需要改 `__init__.py`**,
> 函式名稱直接用就好。

**② 註冊到分派表**

編輯 `/home/bcp_runner/scripts/clean_remote.py`,在 `CLEAN_FUNC_MAP` 加一行:

```python
    CLEAN_FUNC_MAP = {
        "T_TXN_PS": clean_t_txn_ps,
        "T_TXN_PS_FIRST": clean_t_txn_ps,
        "T_CUST": clean_t_cust,
        "T_NEW_TABLE": clean_t_new_table,     # ← 加這行
        # 之後有其他表的清洗邏輯就加在這裡
    }
```

**key 是 `table_mapping.py` 裡的表名**(Dagster 用 `--table` 傳過去的值),
value 是你剛才定義的函式名稱。兩張表可以共用同一支函式(像 `T_TXN_PS` 跟 `T_TXN_PS_FIRST`)。

**③ 忘記註冊會怎樣**

執行時會直接報:
```
ValueError: 找不到 T_NEW_TABLE 的清洗邏輯
```
這種錯誤重跑一百次也一樣,要補上註冊才會好。

### 3-3 ZIP 密碼(只有設了 `use_ftp_zip: True` 才需要)

在 VM1 的 `.env` 加一行,**變數名稱固定是 `ZIP_PWD_` + 表名大寫**:

```
ZIP_PWD_T_NEW_TABLE=實際密碼
```

密碼本身**不會**經過 Dagster——Dagster 只傳「環境變數的名字」過去。\
之後資料封存也會採用此原密碼。

## Step 4 · 讓 dbt 可以引用這張表(要用到才需要)

編輯 `dagster_workspace/dbt_project/models/sources.yml`,在 `database` 這個 source 底下加一行:

```yaml
      - name: T_NEW_TABLE
```

之後 dbt 模型裡就能寫 `{{ source('database', 'T_NEW_TABLE') }}`。
**沒登記的話,dbt 編譯階段就會直接失敗。**

## Step 6 · 驗證

### 6-1 確認資產出現

**Catalog** 頁面搜尋 `key:"*T_NEW_TABLE*"`,應該看到:

| 資產 | 出現條件 |
|---|---|
| `file_system/T_NEW_TABLE_fetch_ftp` | 有開 `use_ftp_fetch` |
| `file_system/T_NEW_TABLE_named` | 有開 `use_data_rule` |
| `file_system/T_NEW_TABLE_encrypted` | 有給 `encrypt_fields` |
| `file_system/T_NEW_TABLE_clean` | 有開 `has_clean_func` |
| `database/T_NEW_TABLE` | 一定會有 |
| `file_system/T_NEW_TABLE_archive_cleanup` | 有開 `use_ftp_fetch` |

群組應該是 `extract_load`(日檔)或 `monthly_extract_load`(月檔)。

### 6-2 一個節點一個節點手動跑

**不要一次跑整條鏈。** 從第一個節點開始,選一個有實際檔案的日期:

```
① fetch_ftp    → 跑完去 VM1 確認 ~/<staging>/ 底下有檔案
② named        → 確認 _NAMED.csv 產生，欄位名正確
③ encrypted    → 確認 _ENCRYPTED.csv 產生，敏感欄位已變成密文
④ clean        → 確認 _CLEAN.csv 產生，筆數與內容合理
⑤ database     → 查資料庫 SELECT COUNT(*)，並看 bcp_error_logs 有沒有錯誤列
⑥ archive_cleanup → 確認 archive_dir 裡只剩一個 zip，中繼檔都清掉了
```

### 6-3 確認 sensor 掃得到

**Automation** → 對應的 watcher → 最近一筆 tick 的 log,應該看到:

```
[T_NEW_TABLE] 監控目錄: /data/fromFPP/T_NEW_TABLE (mode=ftp), 找到: [...]
```

沒看到的話,對照:

| 情況 | 原因 |
|---|---|
| 完全沒有這張表的訊息 | `freq` 填錯,或設了 `manual_only: True` |
| `找到: []` | 目錄空的,或副檔名不符(zip 表只看 `.zip`) |
| 有找到但沒觸發 | 檔案 mtime 未滿 60 秒(離峰時間 5 分鐘，可調整 cursor),或這個日期已經處理過 |
