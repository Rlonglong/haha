## 一、現在的邏輯是什麼

### 1-1 三組連線資訊各自放在哪

| 連線 | 設定在哪 | 值 |

### 1-2 路徑常數

| 常數 | 值 | 用途 |
|---|---|---|
| `DBT_PROJECT_DIR` | `/app/workspace/dbt_project` | dbt 專案(容器內) |
| `CONTAINER_DATA_DIR` | `/run/media/root/D/data/` | **相對路徑的基準**——設定檔裡的相對路徑都會接在它後面 |
| env 檔位置 | `/app/workspace/dagster_code/.env` | 資料庫帳密 |
| dbt 掛載來源 | `/data/deploy/workspace/dagster_workspace/dbt_project` | VM4 host 上的實際路徑 |
| dbt 網路 | `docker-compose_vm4-network` | dbt 容器要接的 docker network |

相對/絕對路徑的處理:

```python
def resolve_path(base_dir: str, target_path: str) -> str:
    if not target_path:
        return base_dir
    if os.path.isabs(target_path):
        return target_path
    return os.path.join(base_dir, target_path)
```

**設定檔裡寫絕對路徑就照用,寫相對路徑就接在 `/run/media/root/D/data/` 後面。**

### 1-3 VM1 上的環境變數

| 變數 | 用途 | 誰讀 |
|---|---|---|
| `ZIP_PWD_<表名大寫>` | 解密 FTP 的 zip | `fetch_ftp_remote.py`、`archive_cleanup_remote.py` |
| `SOURCE_DECRYPT_KEY`(或 `decrypt_key_env` 指定的名字) | 解來源 DB 的密文 | `extract_source_db.py` |

**Dagster 只傳「變數的名字」過去,密碼本身完全不經過 SSH 指令。**

```python
    zip_password_env_key = f"ZIP_PWD_{table_name.upper()}" if use_ftp_zip else None
    ...
                command += ["--zip-password-env-key", zip_password_env_key]
```

### 1-4 指令是怎麼送到 VM1 的

```python
            env_assignments = " ".join(
                f"{k}={shlex.quote(str(v))}" for k, v in env_vars.items()
            )
            quoted_command = shlex.join(str(c) for c in command)
            remote_command = f"{env_assignments} {quoted_command}"
```

**每一個值都經過 `shlex.quote()`**,所以路徑或參數裡就算有 `;` `` ` `` `$()` 也只會被當成字面值,
不會變成額外的指令。這是刻意的注入防護,**改動這段要非常小心**。

## 二、想調什麼,改哪裡

### 調整 A:換 VM1 的位址或帳號

```python
# pipes_ssh_client.py
SSH_HOST     = "10.10.159.74"        # ← 改這裡
SSH_USER     = "bcp_runner"

```

改完要確認:
- [ ] Dagster 容器裡的金鑰檔存在且權限是 `600`
- [ ] 從容器裡手動 `ssh` 測得通:
      ```bash
      ssh -i /home/dagster_user/.ssh/dagster_to_vm1 bcp_runner@新IP 'echo ok'
      ```
- [ ] `sensors.py` 也 import 了這三個常數(它自己會 SSH 列目錄),不需另外改

**更好的做法**:改成從環境變數讀,這樣不同環境不用改程式:

```python
import os
SSH_HOST     = os.getenv("VM1_SSH_HOST", "10.10.159.74")
SSH_USER     = os.getenv("VM1_SSH_USER", "bcp_runner")
SSH_KEY_PATH = os.getenv("VM1_SSH_KEY_PATH", "/home/dagster_user/.ssh/dagster_to_vm1")
```

### 調整 F:改 Dagster 實例設定

`dagster_home/dagster.yaml` 的內容:

| 設定 | 目前值 | 意義 |
|---|---|---|
| `max_concurrent_runs` | `5` | 同時最多幾個 Run |

## 三、改完怎麼驗證

| 改了什麼 | 驗證方式 |
|---|---|
| SSH 設定 | 容器內手動 ssh 測試 → Reload → 手動跑一個 `*_fetch_ftp` 節點 |
| `.env` | Reload → 手動跑一個有 `use_partition` 的表(它會用 pymssql 連 DB) |
| `profiles.yml` | 手動 `dbt compile` → 沒有 `Env var required but not provided` 就對了 |
| `CONTAINER_DATA_DIR` | Reload → 看資產的 log 裡印出來的路徑對不對 |
| `dagster.yaml` | **重啟容器** → Deployment 頁面確認設定生效 |

## 四、安全注意事項

| 事項 | 說明 |
|---|---|
| **`.env` 不進版控** | 確認 `.gitignore` 有排除它 |
| **`profiles.yml` 不要寫回明碼** | 曾經因為明碼進版控而需要輪換密碼,不要重蹈覆轍 |
| **`shlex.quote()` 不要拿掉** | 那是唯一擋住指令注入的地方 |
| **白名單驗證不要放寬** | `validate_sql_identifier` / `validate_path_component` 擋的是 SQL 注入與路徑穿越 |
| **錯誤訊息可能含敏感資訊** | 要把 log 送到外部系統之前先過濾 |
